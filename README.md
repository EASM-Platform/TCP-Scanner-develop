# TCP-Scanner-develop
사용자가 IP, 도메인, CIDR을 입력하면 TCP Connect 기반 포트 스캔을 수행하고, 열린 포트에 대해 Nmap으로 서비스와 버전을 식별한 뒤, 규칙 기반 위험도 분석과 웹 포트 자동 캡처를 거쳐 JSON/HTML 리포트를 생성하는 구조

1. 입력 계층
사용자로부터 IP, 도메인, CIDR 대역을 입력받는다.
도메인은 IP로 변환하고, CIDR은 여러 개의 IP 목록으로 확장한다.

2. 스캔 계층
확정된 대상 IP들에 대해 TCP Connect 방식으로 주요 포트를 스캔한다.
이 단계에서 열린 포트와 닫힌 포트를 구분한다.

3. 서비스 분석 계층
열린 포트만 다시 Nmap으로 분석하여 서비스명, 제품명, 버전 정보를 수집한다.

4. 위험도 분석 계층
Nmap 결과를 바탕으로 서비스별 규칙을 적용해 위험, 주의, 일반, 알 수 없음으로 분류하고 이유를 함께 생성한다.

5. 시각화 보조 계층
웹 서비스로 식별된 포트(예: 80, 8000 등)에 대해서는 Selenium 기반 자동 접속을 수행하고 화면을 캡처하여 저장한다.

6. 리포트 생성 계층
최종적으로 스캔 결과, 서비스 분석 결과, 위험도 분류 결과, 웹 캡처 결과를 JSON과 HTML 리포트로 저장한다.

Input/Resolver 모듈: IP, 도메인, CIDR 처리
Port Scanner 모듈: TCP Connect 기반 포트 스캔
Nmap Analyzer 모듈: 서비스/버전 식별
Risk Analyzer 모듈: 규칙 기반 위험도 판단
Web Capture 모듈: 웹 포트 자동 캡처
Report Generator 모듈: JSON/HTML 결과 생성

위 시스템은 입력 처리, 포트 스캔, 서비스 분석, 위험도 판단, 웹 캡처, 리포트 생성의 6단계 파이프라인 구조로 설계하였다.
먼저 사용자가 입력한 IP, 도메인, CIDR 대역을 해석하여 실제 스캔 대상 목록을 생성하고, TCP Connect 기반 포트 스캔을 통해 열린 포트를 탐지한다. 
이후 열린 포트에 대해서만 Nmap 분석을 수행하여 서비스명과 버전 정보를 식별하고, 규칙 기반 위험도 분석을 통해 각 서비스의 보안상 주의 여부를 판단한다.
또한 웹 서비스로 식별된 포트에 대해서는 자동 캡처를 수행하여 시각적 증거를 확보하고, 최종 결과를 JSON 및 HTML 리포트 형태로 출력하도록 구성하였다
